Preparing for AWS Cloud Practitioner

My learning journey through AWS Cloud fundamentals and the key concepts behind cloud computing, security, storage, compute, networking, monitoring, and cost optimization.

Dec 15, 2025 • 4 min read
AWSCloudCLF-C02

As a backend developer, I build applications that eventually have to run somewhere. I wanted to understand that "somewhere" properly, so I started preparing for the AWS Certified Cloud Practitioner (CLF-C02) exam. It is the entry-level AWS certification, and it is less about deep technical configuration and more about understanding what the cloud offers and how the pieces fit together. Here is what I have been studying and how I organize it.

What the Exam Covers

The CLF-C02 exam guide groups the content into four domains:

  • Cloud Concepts (24%): the value of the cloud and the design principles behind it.
  • Security and Compliance (30%): the shared responsibility model, IAM, and security services.
  • Cloud Technology and Services (34%): the core compute, storage, database, and networking services.
  • Billing, Pricing, and Support (12%): pricing models, cost tools, and support plans.

Security and core services together make up almost two thirds of the exam, so that is where I spend most of my time.

Cloud Concepts

The core idea is trading fixed, upfront infrastructure costs for variable, on-demand costs. Instead of buying servers for peak traffic, you scale with demand. Key ideas to understand:

  • Elasticity and scalability: adding and removing capacity automatically.
  • High availability: AWS Regions contain multiple Availability Zones, and spreading an application across them protects it from a single data center failure.
  • The Well-Architected Framework: six pillars covering operational excellence, security, reliability, performance efficiency, cost optimization, and sustainability.

Security and the Shared Responsibility Model

This is the concept I consider most important. AWS is responsible for security of the cloud: the physical data centers, hardware, and the underlying infrastructure. The customer is responsible for security in the cloud: their data, IAM configuration, operating system patches on EC2, network rules, and encryption choices.

On the identity side, IAM is the foundation:

  • Never use the root account for daily work, and protect it with MFA.
  • Grant permissions through roles and groups, following the principle of least privilege.
  • Prefer IAM roles over long-lived access keys, especially for applications running on AWS.

Coming from building RBAC into applications, IAM policies felt familiar: they are permissions attached to identities, just at the infrastructure level.

Core Services I Focus On

Compute

  • EC2: virtual servers with full control over the operating system.
  • Lambda: serverless functions that run on demand and are billed per execution.
  • Elastic Beanstalk and ECS: managed ways to deploy applications and containers.

Storage

  • S3: object storage with storage classes for different access patterns and costs.
  • EBS: block storage volumes attached to EC2 instances.

Databases

  • RDS and Aurora: managed relational databases.
  • DynamoDB: a managed NoSQL key-value and document database.

Networking and Monitoring

  • VPC: an isolated network with subnets, route tables, and security groups.
  • CloudFront and Route 53: content delivery and DNS.
  • CloudWatch and CloudTrail: metrics and logs on one side, an audit trail of API calls on the other.

Billing and Pricing

Understanding how AWS charges is essential for real projects, not just the exam:

  • On-Demand: pay by the hour or second with no commitment.
  • Savings Plans and Reserved Instances: lower prices in exchange for a one- or three-year commitment.
  • Spot Instances: large discounts on spare capacity that can be interrupted.
  • Cost tools: AWS Budgets for alerts, Cost Explorer for analysis, and the Pricing Calculator for estimates.

How I Study

  1. Official material first. The exam guide and AWS Skill Builder define the scope, which prevents studying things that are not on the exam.
  2. Hands-on practice. Using the Free Tier to launch an EC2 instance, create an S3 bucket, and write an IAM policy makes the concepts stick far better than reading.
  3. Compare similar services. Many questions test whether you can pick the right service, such as RDS vs DynamoDB or EC2 vs Lambda, so I keep a comparison table.
  4. Practice questions. They reveal weak areas and get you used to the wording of scenario-based questions.

One habit I strongly recommend: set up an AWS Budget alert on day one of practicing, so an experiment you forgot to delete never becomes a surprise bill.

Update, October 2026: This preparation paid off. I passed the AWS Certified Cloud Practitioner (CLF-C02) exam in August 2026, and went on to earn the AWS Certified Developer – Associate certification in October 2026.

Why It Matters for a Developer

Even as an entry-level certification, CLF-C02 changed how I think about the applications I build. I now think about where logs go, how a service would scale, who has access to what, and what the infrastructure costs. It is also the first step on my path toward DevOps and SRE, which I write about in From Full Stack Development to DevOps and SRE.
