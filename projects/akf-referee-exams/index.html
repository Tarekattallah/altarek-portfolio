African Karate Federation — Referee Examinations

An in-hall examination platform with timed tests, automatic question progression, answer tracking, and automated scoring.

Node.js PostgreSQL REST API RBAC
Live Demo

Overview

The African Karate Federation Referees Committee needed a reliable way to run referee certification exams inside an examination hall. I developed an in-hall examination platform, now live at referees.africankaratefederation.org, built with Node.js, PostgreSQL, and REST APIs.

The Problem

Running a fair exam for a room full of referees is harder than it looks:

  • Creating and managing an account for every candidate adds friction and support work on exam day.
  • If each device controls its own timer, candidates can end up with different amounts of time.
  • Grading by hand is slow, and results must stay private to the committee.

The Solution

The platform treats the exam as a single, server-controlled session that every candidate joins and moves through together:

  • QR-based entry: referees scan a QR code in the hall and identify themselves. There are no candidate accounts; a secure, non-guessable session token admits them to that hall session only.
  • Server-authoritative timing: the instructor starts the exam once. Every question has the same duration and advances automatically from the official start timestamp, so all candidates progress on the same timeline.
  • Answer tracking and automatic grading: answers are recorded as candidates go, attempts auto-submit when time ends, and scoring is automatic.
  • Staff-only results: administrator and instructor roles manage exams centrally; results and activity timelines are visible to staff only.

Server-Authoritative Timing

The key design decision was to never trust the candidate's device clock. The server stores the official start time, and the current question is always derived from it. A simplified version of that logic:

// Simplified illustration: the server decides which question is active
function currentQuestion(session, now = Date.now()) {
    const elapsed = now - session.startedAt;
    const index = Math.floor(elapsed / session.secondsPerQuestion / 1000);

    if (index >= session.questionCount) {
        return { finished: true };
    }
    const endsAt = session.startedAt + (index + 1) * session.secondsPerQuestion * 1000;
    return { index, remainingMs: endsAt - now };
}

A device that refreshes, reconnects late, or has a wrong clock simply asks the server where the exam is and resumes at the correct question with the correct remaining time.

Engineering Challenges

Fairness without accounts. Removing candidate accounts made the experience simpler but raised a security question: how do you admit the right people? Scoping a non-guessable token to one hall session solved it without registration.

Many devices, one timeline. Keeping a whole room in sync meant designing the API so clients are views of the server's state, not owners of their own timers.

Lessons Learned

Building for a real organization in a live exam setting taught me to design around the environment the software actually runs in, and to keep the source of truth on the server whenever fairness is at stake.
