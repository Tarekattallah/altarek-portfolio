Egyptian Judicial Fees — Court Fee Calculation Platform

An Arabic RTL platform for court fee estimation and settlement review, with precise rule-based calculations and traceable legal references.

React TypeScript Express PostgreSQL Prisma RBAC

Overview

The Egyptian Judicial Fees platform is an Arabic, right-to-left web application for estimating court fees and reviewing settlements. I worked on it during my Full Stack Development training at the Ministry of Justice (September – October 2026), contributing to the calculation engine, access control, auditing, and dashboards using React, TypeScript, Express, PostgreSQL, and Prisma.

The Problem

Court fees depend on legal rules that vary by case type, claim value, and exemptions. When these calculations are done manually or in spreadsheets, three problems appear:

  • Inconsistency: two reviewers can reach different amounts for the same case.
  • Missing justification: a number on its own does not show which legal article it came from.
  • Weak accountability: it is hard to prove who changed a rule or approved an assessment, and when.

The platform needed to make every fee reproducible, explainable, and auditable.

The Solution

The system turns the fee rules into structured, versioned data and runs every assessment through the same rule-based engine. Each calculated line is linked to the legal reference it is based on, so a reviewer can trace any amount back to its source.

  • Precise rule-based calculations: fees are computed from approved rules, not typed in by hand, so the same inputs always give the same result.
  • Traceable legal references: every line in an assessment shows the article it applies.
  • Independent rule approvals: a change to a calculation rule is a draft until a different authorized user approves it, so no single person can change how fees are calculated.
  • Role-based access control: estimators, reviewers, and administrators each see and do only what their role permits.
  • Assessment and settlement dashboards: reviewers track pending assessments, approved fees, and settlements in one place.
  • Arabic RTL interface: the whole UI is built right-to-left for its Arabic-speaking users.

Tamper-Evident Audit Logs

Because assessments have legal weight, the audit trail had to be trustworthy. Audit entries are hash-chained with SHA-256: each entry stores the hash of the previous one, so editing or deleting any past entry breaks the chain and is immediately detectable. A simplified version of the idea:

// Simplified illustration of a hash-chained audit entry
const crypto = require('crypto');

function createAuditEntry(previousHash, event) {
    const payload = JSON.stringify({ ...event, previousHash, at: new Date().toISOString() });
    const hash = crypto.createHash('sha256').update(payload).digest('hex');
    return { ...event, previousHash, hash };
}

// Verifying the chain: every entry must point to the hash before it
function verifyChain(entries) {
    return entries.every((entry, i) => i === 0 || entry.previousHash === entries[i - 1].hash);
}

Engineering Challenges

Correctness over convenience. Money and legal rules leave no room for rounding surprises or edge cases that "usually" work. Calculation and permission logic is covered by automated tests, so a rule change or refactor cannot silently alter results or open access that should be closed.

Separating rules from code. Keeping the fee rules as approved data (managed through PostgreSQL and Prisma) rather than hard-coded logic means the legal rules can evolve through the approval workflow without redeploying the application.

Lessons Learned

This project showed me how much trust matters in government software. Features like independent approvals and tamper-evident logs are not extras; they are what makes the numbers credible. It also reinforced the value of TypeScript and automated tests when the business rules are strict and the cost of a mistake is high.
