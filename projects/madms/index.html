MADMS — Enterprise Management System

A modular enterprise management system designed with a scalable backend architecture and structured business modules.

Node.js Express.js MongoDB RBAC

Overview

MADMS is a robust, modular enterprise management system built to handle complex, real-world business operations. The system manages core enterprise data, including student management, attendance, complaint handling, and phone requests, all bound together by a strict role-based access control (RBAC) system.

The Problem

Enterprise applications often suffer from closely coupled code where routing, validation, database queries, and business logic are mixed together. This leads to difficult maintenance, challenging testing, and a system that breaks easily when new modules are added.

The Solution & Architecture

To solve this, MADMS is built entirely on a highly decoupled, modular architecture designed for scalability. The system forces a strict separation of concerns through the following layers:

Router → Controller → Service → Repository → Model
  • Controllers: Handle HTTP requests and responses only.
  • Services: Contain the core business rules and logic.
  • Repositories: Abstract the database operations (Mongoose queries).
  • Models: Define the MongoDB schemas and data structure.

Key Features

  • Modular Architecture: Code is organized by business feature, not file type.
  • Authentication & Authorization: JWT-based secure authentication.
  • RBAC (Role-Based Access Control): Dynamic permissions mapping users to roles.
  • Robust Validation: Strict payload validation using Joi.
  • Soft Delete & Public IDs: Records are never truly deleted, preserving audit history. Internal database IDs (_id) are hidden behind secure public identifiers.
  • Centralized Error Handling: Consistent API error responses.

Engineering Challenges

One of the primary challenges was designing the RBAC module to be completely dynamic while remaining performant. Since every API endpoint needs authorization checks, I implemented middleware that efficiently verifies if a user's role grants them the specific permission required for the requested resource, without unnecessarily hitting the database on every single request.

Lessons Learned

Building MADMS reinforced the importance of the Repository Pattern. By abstracting the database layer, the business logic became much easier to reason about. Additionally, handling Soft Deletes and Public IDs early in the database design phase prevented significant refactoring later on.
